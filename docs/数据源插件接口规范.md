## 1. 概述

### 1.1 目标

本规范定义「动漫更新看板」（下称**宿主**）与「数据源插件」（下称**插件**）之间的标准接口。任何动漫站点只要按本规范实现一个插件，即可作为数据源接入看板，**无需修改宿主代码**。

核心诉求：不同站点的解析方法可能完全不同——有的提供 JSON API，有的只能解析 HTML 页面，有的混合使用。因此本规范只约束**输入、输出与行为**（接口签名、数据模型、错误语义、频率礼貌），把**解析实现**的自由完全留给插件。

### 1.2 读者

- **插件开发者**（主要读者）：为某个动漫站点编写解析插件。
- **宿主维护者**：实现插件宿主（PluginHost）、加载器与沙箱。

### 1.3 版本策略

- 规范版本由 `manifest.manifestVersion` 声明；主版本号变更代表不兼容演进，次版本号只增不改。
- 宿主承诺支持同主版本的全部次版本（如宿主声明支持 `1.0` 即兼容所有 `1.x`）；加载更高主版本的插件时应拒绝并提示升级宿主。
- 规范变更必须同步更新本文档变更记录与架构文档。

## 2. 术语与角色

| 术语 | 定义 |
| --- | --- |
| 宿主 | 动漫更新看板前端应用本体 |
| 插件 | 符合本规范的一个站点解析包，= 清单（manifest）+ 实现代码 |
| 沙箱 | 插件代码的执行环境（Worker 或主线程），决定隔离强度 |
| 能力（capability） | 插件声明并提供的一类数据服务，如 `search`、`detail` |
| 权限（permission） | 插件向宿主申请的资源，如允许请求的域名、私有存储 |
| 领域模型 | 宿主定义的统一数据结构（见 §7），插件负责把站点原始数据映射成它 |
| 夹具 | 录制的真实站点响应样本，用于插件回归测试（见 §13） |

## 3. 插件形态与沙箱

| 形态 | 加载方式 | 沙箱 | 适用 |
| --- | --- | --- | --- |
| `builtin` 内置插件 | 随应用一起构建发布 | `worker` 或 `main`（开发者选择） | 首批官方数据源（如 agedm），随版本迭代 |
| `remote` 外置插件 | 用户在设置页添加插件地址，宿主动态加载 | **强制 `worker`** | 第三方/社区站点接入，可独立于宿主发版 |

沙箱语义：

- **`worker`（推荐）**：插件运行在 Web Worker 中，与页面 DOM、宿主全局完全隔离；对网络、存储的访问只能通过宿主注入的 `PluginContext`（经 postMessage 桥接）。第三方代码默认走此形态。
- **`main`**：插件与宿主共享主线程，可用完整 DOMParser；**无安全隔离**，仅建议内置插件使用。规范层面允许，文档须提示风险。

## 4. 清单（manifest）规范

插件必须提供一份 JSON 清单，宿主以它做校验、权限确认与能力协商。

### 4.1 字段定义

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `manifestVersion` | string | 是 | 规范版本，当前 `"1.0"` |
| `id` | string | 是 | 插件唯一标识，`/^[a-z0-9][a-z0-9-]{1,31}$/`，建议含站点域名词根 |
| `name` | string | 是 | 展示名（如 "Age动漫"） |
| `version` | string | 是 | 插件自身版本，semver |
| `siteUrl` | string | 是 | 源站入口 URL（https） |
| `icon` | string | 否 | 图标 URL（https） |
| `type` | string | 是 | `"builtin"` \| `"remote"` |
| `entry` | string | 是 | 入口脚本：builtin 为包内路径；remote 为 https URL |
| `sandbox` | string | 是 | `"worker"` \| `"main"`；remote 强制 `"worker"` |
| `capabilities` | string[] | 是 | 声明的能力，子集：`weekly` / `latest` / `search` / `detail` / `play` / `catalog` / `rank`（后两个为 v1.2 扩展能力）；**声明即必须实现** |
| `permissions.domains` | string[] | 是 | 允许插件请求的域名列表（后缀匹配，如 `"agedm.io"` 含其子域）；宿主强制校验 |
| `permissions.storage` | boolean | 否 | 是否需要插件私有 KV 存储，默认 `false` |
| `config` | ConfigField[] | 否 | 用户可配置项声明（如接口地址覆盖），见 §4.2 |
| `cacheHints` | object | 否 | 各能力的缓存 TTL（秒），如 `{ "latest": 600, "detail": 3600 }`；缺省值见 §8.5 |
| `description` | string | 否 | 一句话描述 |
| `author` | string | 否 | 作者/来源 |
| `sha256` | string | 否 | 仅 remote：entry 脚本 sha256（hex），宿主校验完整性 |

### 4.2 config 配置项字段（`config[]` 元素）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `key` | string | 是 | 配置键，传入 `init(config)` |
| `label` | string | 是 | 设置页展示名 |
| `type` | string | 是 | `"string"` \| `"number"` \| `"boolean"` \| `"select"` |
| `default` | 任意 | 否 | 默认值 |
| `options` | array | select 时必填 | `{ value, label }[]` |
| `required` | boolean | 否 | 默认 `false` |
| `placeholder` | string | 否 | 输入提示 |

### 4.3 清单示例

```jsonc
{
  "manifestVersion": "1.0",
  "id": "agedm",
  "name": "Age动漫",
  "version": "1.2.0",
  "siteUrl": "https://m.agedm.io",
  "type": "builtin",
  "entry": "plugins/sources/agedm/index.ts",
  "sandbox": "main",
  "capabilities": ["weekly", "latest", "search", "detail", "play", "catalog", "rank"],
  "permissions": { "domains": ["agedm.io"], "storage": false },
  "config": [
    { "key": "apiBaseUrl", "label": "接口地址", "type": "string",
      "placeholder": "留空使用默认" }
  ],
  "cacheHints": { "weekly": 600, "latest": 600, "search": 0, "detail": 3600, "play": 0, "catalog": 600, "rank": 1800 },
  "author": "AnimeShortcut"
}
```

> 注：builtin 插件沙箱可按 §3 选 `main`（实现期选择，换取完整 DOMParser）；`remote` 插件强制 `worker`。

## 5. 插件实现接口

### 5.1 TypeScript 定义

```ts
type PluginCapability = 'weekly' | 'latest' | 'search' | 'detail' | 'play';

/** 宿主加载入口：默认导出一个工厂函数（ESM） */
type PluginFactory = (host: PluginContext) => AnimeSourcePlugin | Promise<AnimeSourcePlugin>;

interface AnimeSourcePlugin {
  readonly manifest: PluginManifest;

  /** 生命周期：每次启用或 config 变更后调用，必须幂等 */
  init(config: Record<string, string | number | boolean>): Promise<void>;

  /** 能力方法（均须与 manifest.capabilities 一致；未声明的方法宿主不调用）。
   *  扩展能力 catalog / rank 的方法定义见 §15。 */
  getWeeklySchedule?(page?: number): Promise<PagedResult<AnimeSummary>>;
  getLatestUpdates?(page?: number): Promise<PagedResult<AnimeSummary>>;
  search?(keyword: string, page?: number): Promise<PagedResult<AnimeSummary>>;
  getDetail?(animeId: string): Promise<AnimeDetail>;
  resolvePlay?(animeId: string, episodeId: string): Promise<PlayResult>;

  /** 可选生命周期钩子 */
  onConfigChange?(config: Record<string, string | number | boolean>): Promise<void>;
  onUnload?(): Promise<void>;
}

interface PagedResult<T> { items: T[]; page: number; hasMore: boolean; }

/** resolvePlay 的返回 */
interface PlayResult {
  type: 'page' | 'stream';   // page=跳转源站播放页；stream=站内播放（m3u8 等）
  url: string;               // https
  referer?: string;          // stream 时建议的 Referer（宿主播放器尽力满足）
}
```

UMD/IIFE 形式的 remote 插件：将工厂函数挂到全局 `__AS_PLUGIN__`（`window.__AS_PLUGIN__ = factory`），宿主取不到 ESM 默认导出时回退读该全局。

### 5.2 生命周期

| 阶段 | 宿主动作 | 插件约定 |
| --- | --- | --- |
| 加载 | 校验 manifest → 沙箱启动 → 注入 ctx | 不做任何网络请求 |
| init | 传入合并后的 config | 幂等初始化（可预热常量、解析配置） |
| 服务期 | 按需并发调用能力方法 | 方法无状态、可重入 |
| config 变更 | 调 `onConfigChange`（未实现则重新 `init`） | 使内部派生状态失效 |
| 停用/卸载 | 调 `onUnload` 后终止沙箱 | 释放可释放的资源；私有存储按用户选择保留或清除 |

## 6. 宿主上下文（PluginContext）

`PluginContext` 是插件访问外部世界的**唯一通道**；直接访问 `window`/`fetch`/`XMLHttpRequest` 视为违规实现（worker 沙箱下也物理不可行）。

```ts
interface PluginContext {
  env: { hostVersion: string; specVersion: '1.0'; locale: string; timezone: string; mode: 'dev' | 'production' };

  http: {
    getJson<T>(url: string, opts?: HttpOptions): Promise<T>;
    getText(url: string, opts?: HttpOptions): Promise<string>;
    /** 进阶：需要状态码/响应头/二进制时使用（worker 沙箱下 body 以 ArrayBuffer 传输） */
    getRaw(url: string, opts?: HttpOptions): Promise<RawResponse>;
  };

  /** 轻量 HTML 解析（全沙箱可用；宿主主线程 DOMParser 执行，经桥接返回） */
  dom: {
    query(html: string, selector: string, opts?: { attr?: string; all?: boolean })
      : Promise<string | string[] | null>;   // 默认取首个元素的 textContent；attr 指定取属性（支持特殊值 "outerHTML"/"innerHTML"，用于分块二次解析）；all 返回全部
  };

  /** 完整 DOMParser 文档（仅 sandbox: main 时存在；worker 沙箱下为 undefined） */
  domDocument?: { parse(html: string): Document };

  /** 插件私有 KV（命名空间 asc:plugin:<id>:，自动隔离；建议用量 ≤ 1MB） */
  storage: {
    get<T>(key: string): Promise<T | null>;
    set(key: string, value: unknown): Promise<void>;
    delete(key: string): Promise<void>;
    keys(): Promise<string[]>;
  };

  /** 带 [pluginId] 前缀，进入宿主日志面板（设置页可查看，便于调试插件） */
  log: { debug(...a: unknown[]): void; info(...a: unknown[]): void; warn(...a: unknown[]): void; error(...a: unknown[]): void };

  utils: {
    absUrl(base: string, path: string): string;   // 相对地址 → 绝对地址
    decodeEntities(text: string): string;          // HTML 实体解码
    hashId(input: string): string;                 // 稳定短 id（源站无稳定 id 字段时可用）
  };
}

interface HttpOptions {
  timeoutMs?: number;               // 默认 10_000，上限 30_000
  headers?: Record<string, string>; // 宿主可能覆盖危险头（UA/Referer 等由宿主统一管理）
  referer?: string;                 // 期望的 Referer（代理链尽力满足）
  ttlMs?: number;                   // 本次请求的宿主层去重缓存 TTL（默认 0）
}
```

### 6.1 宿主对 http 的强制约束

| 约束 | 规则 |
| --- | --- |
| 域名白名单 | 仅允许 `manifest.permissions.domains` 后缀匹配的域名；越界抛 `DOMAIN_NOT_ALLOWED` |
| 开发联调例外 | `import.meta.env.DEV` 下允许同源相对路径（配合 Vite dev server 代理，免部署外部代理即可联调真实数据）；生产严格白名单 |
| 方法 | v1 仅 GET |
| 限流 | 每插件并发 ≤ 2、QPS ≤ 1，超出自动排队 |
| 代理链 | 请求自动走宿主代理链（直连 → 自部署 Worker → 公共代理回退），插件无感 |
| 失败语义 | 失败抛宿主错误（含 cause），插件按 §9 处理或向上传播 |

## 7. 统一数据模型

### 7.1 模型定义

```ts
/** 列表项（周更表/最新更新/搜索共用） */
interface AnimeSummary {
  animeId: string;                 // 必填，插件源内稳定唯一
  title: string;                   // 必填，纯文本
  cover?: string;                  // https 图片 URL
  weekday?: number;                // 0~6，0=周日；语义见 §7.3
  latestEpisodeTitle?: string;
  updateTime?: number;             // 毫秒时间戳（Unix epoch, UTC）
  playPageUrl?: string;            // 源站播放页（可直接打开）
}

interface AnimeDetail extends AnimeSummary {
  description?: string;            // 纯文本（宿主按纯文本渲染，不做 HTML 展示）
  region?: string;                 // 地区/年份等元信息
  genres: string[];                // 标签
  status?: 'ongoing' | 'finished' | 'unknown';
  episodes: Episode[];             // 必填（可为空数组，表示暂无剧集数据）
}

interface Episode {
  episodeId: string;               // 必填，插件源内稳定唯一
  title: string;                   // 必填，纯文本
  playPageUrl?: string;            // 跳转播放用
  updateTime?: number;
  line?: string;                   // 所在线路显示名（无线路概念可缺省）【v1.1 追加】
  lineIndex?: number;              // 线路序号，0-based【v1.1 追加】
  episodeIndex?: number;           // 集序号，0-based【v1.1 追加】
}
```

### 7.2 宿主注入与复合主键

- **`sourceId` 由宿主注入**（= manifest.id），插件**无需也不应**在返回值中携带。
- 全局唯一键为 `${sourceId}:${animeId}`，剧集为 `${sourceId}:${animeId}:${episodeId}`，由宿主生成，插件只保证 `animeId` / `episodeId` 在源内稳定。
- 有多线路的站点建议 `episodeId` 采用 `${lineIndex}:${episodeIndex}`（均为 0-based）格式，并同步填充 `line` / `lineIndex` / `episodeIndex`，宿主详情页据此做线路分组展示（agedm 插件即此形态）。
- 源站无稳定 id 时，插件可用 `utils.hashId(稳定字符串)` 生成，但必须在插件内**长期稳定**（换 id 等于订阅失效）。

### 7.3 时区与 weekday 语义

- `weekday` 表示番剧的**更新档期**，按动漫行业惯例以**日本时间（UTC+9）**为准：数据源给出具体日期/时间时，插件应换算到 UTC+9 再取星期；源站仅给"周三更新"这类档期文字时直接映射。
- 无法确定时缺省（undefined），宿主将其归入周更表「未定档」分组，不得猜测。
- `updateTime` 一律为毫秒级 Unix 时间戳；源站时间无时区标注且无法推断时，可缺省，不得虚构。

### 7.4 字段净化

- 所有文本字段（title/description/genres 等）必须是**纯文本**：不允许 HTML 标签；实体由插件用 `utils.decodeEntities` 或 `dom.query` 解除。
- 所有 URL 仅允许 `https:`；`http:` 一律升级或丢弃。
- 宿主对入站数据做二次校验（必填字段、类型、URL 协议），不合格记录记入日志并丢弃该条目。

## 8. 行为契约

1. **能力协商**：`manifest.capabilities` 与实现的方法一一对应；宿主调用前预检，不会调用未声明的方法。
2. **分页**：`page` 从 1 开始；`hasMore=false` 表示没有更多页。周更表可整表单页返回（`hasMore:false`）。
3. **无状态与并发**：能力方法可被并发调用，不得依赖调用顺序或共享可变中间状态；`init` 是唯一初始化点。
4. **单次调用预算**：一次能力方法调用内的上游请求数 ≤ 3（详情页需要聚合多个接口时适用）。
5. **缓存**：宿主按 `cacheHints` 缓存**能力方法结果**（缺省：weekly/latest/catalog 600s、rank 1800s、detail 3600s、search/play 0s）；插件内部不建持久缓存，`onConfigChange`/`init` 后视为缓存失效。并发同 URL 请求由宿主去重。宿主的订阅更新检测会**绕过方法级缓存**取最新数据（fresh 语义）。
6. **超时**：http 请求级默认 10s（上限 30s）；单次能力方法调用宿主级 30s，超时按错误处理。
7. **失败与空结果的区分**：失败必须 throw（见 §9），**不得**用空结果伪装成功；"查无结果"返回 `{ items: [], hasMore: false }`。
8. **解析礼貌**：优先使用站点 JSON API；解析 HTML 时只请求必要页面，禁止一次调用内批量扫描多页。

## 9. 错误码规范

插件抛出的错误须为可识别形状 `{ code, message, cause? }`（普通 `Error` 宿主包装为 `UNKNOWN`）：

| code | 含义 | 宿主处理 |
| --- | --- | --- |
| `TIMEOUT` | 上游请求超时 | 按重试策略重试；UI 提示"请求超时" |
| `NETWORK` | 连接失败（DNS/断网） | 触发代理链切换；UI 提示检查网络/代理 |
| `DOMAIN_NOT_ALLOWED` | 请求了白名单外域名 | 不重试；日志告警（可能是插件 bug） |
| `RATE_LIMITED` | 上游限流（429 等） | 退避重试；UI 提示稍后再试 |
| `PARSE` | 响应解析失败（源站改版/结构变化） | UI 提示"源站可能改版"；记录日志 |
| `UNSUPPORTED` | 调用了未实现能力 | 宿主预检后不应出现 |
| `CONFIG_INVALID` | 配置缺失/非法（如必填 config 为空） | UI 引导打开设置 |
| `UPSTREAM_CHANGED` | 插件自检判定接口结构已变 | 提示"该站点插件需要更新" |
| `UNKNOWN` | 其他 | 记录日志；UI 通用错误 |

## 10. Worker 沙箱消息协议

remote 插件运行于 Module Worker，宿主与插件通过 postMessage 通信。信封格式：

```
宿主 → 插件: { v: 1, id: "<msgId>", op: "invoke", method: "<方法名>", args: [ ... ] }
插件 → 宿主: { v: 1, id: "<msgId>", ok: true,  data: <返回值> }
           | { v: 1, id: "<msgId>", ok: false, error: { code, message, cause? } }

插件 → 宿主（ctx 服务反向调用，宿主为插件实现桩函数）:
           { v: 1, id: "<ctxId>", op: "http.getJson" | "dom.query" | "storage.get" | ..., args: [ ... ] }
宿主 → 插件: { v: 1, id: "<ctxId>", ok: true, data: ... } | { v: 1, id: "<ctxId>", ok: false, error: {...} }
```

- 初始化序列：宿主发 `{ op: "init", args: [manifest, config] }`，插件回 ok 后进入服务期。
- 消息级超时 30s，超时未回视为该次调用失败（`TIMEOUT`）；宿主可终止并重启 Worker。
- 版本协商：首条消息带 `v`，不匹配即终止加载。

## 11. 安装与信任模型（remote 插件）

加载任意第三方代码属于**显式高危操作**，流程如下：

1. 用户在设置页导入插件包文件（`.asplugin.json`，见 §12）或粘贴插件清单/入口 URL；宿主拉取并校验 manifest（schema、manifestVersion 兼容性、domains 合理性、sha256 完整性）。
2. 宿主展示权限摘要（名称、版本、能力、**允许访问的域名**、是否用存储），**用户显式确认后才加载**。
3. 若 manifest 带 `sha256`，校验 entry 脚本哈希；不匹配拒绝加载。
4. Worker 沙箱加载 → init → 探活（调用一个已声明能力）→ 注册进插件注册表。
5. 默认**不开启**外置插件入口；卸载插件时用户可选择清除其私有存储。

宿主侧防御：插件代码永不 `eval` 进主线程、不接触宿主内部模块与用户数据（订阅/历史在宿主存储中，插件仅有自己的命名空间）、http 域名白名单在宿主侧强制。

## 12. 打包与分发

- **内置插件**（仓库内）：

```
src/plugins/
├─ host/                # PluginHost：加载器、沙箱桥、权限校验、注册表、ctx 实现
└─ sources/
   └─ agedm/
      ├─ manifest.ts    # 导出 PluginManifest
      ├─ index.ts       # export default createPlugin（PluginFactory）
      ├─ mapping.ts     # 站点原始结构 → 统一模型
      └─ __fixtures__/  # 录制的真实响应样本（见 §13）
```

- **外置插件**：单文件分发，esbuild/rolldown `--bundle` 打包为自包含 IIFE（无残留 `import`/`export`），工厂函数按 §5.1 挂 `self.__AS_PLUGIN__`；建议托管在 GitHub Raw / jsDelivr 等默认允许跨域的静态源。发布物 = **`.asplugin.json` 插件包**（`{ formatVersion: 1, manifest, code }`，`code` 为 IIFE bundle 文本，manifest 的 `sha256` 指向 `code` 摘要），宿主以它做导入/导出/持久化（IndexedDB）的统一载体，文件导入与清单 URL 导入汇入同一安装管线。宿主内置插件的分发产物由 `npm run pack:plugins` 生成（`public/plugins/<id>.asplugin.json`，dev 可直接访问、构建时拷入 `dist/` 随 Pages 部署，`npm run build` 已串联）。

## 13. 测试规范

- 宿主提供测试夹具工具（开发依赖，如 `@animeshortcut/plugin-test-kit`）：以录制样本回放 http，隔离 storage/log，断言模型校验。
- 夹具命名：`__fixtures__/<capability>-<case>-p<page>.json`，如 `search-keyword1-p1.json`、`latest-normal-p1.json`、`catalog-region-japan-p1.json`、`rank-year-all.json`。
- **最少用例集**（每个插件进 CI 的门槛）：
  1. 每个 `capabilities` 至少 1 个成功用例；
  2. 至少 1 个"空结果"用例（`hasMore: false`）；
  3. 至少 1 个异常样本（如 404 / 结构变化 → 断言抛出正确错误码）；
  4. `getDetail` 用例须校验 `episodes` 与 `playPageUrl`。
- 夹具与真实响应脱敏后入库，不收录任何用户数据。

## 14. 完整示例（agedm 内置插件骨架）

> 以下为**实现落地后的真实形态摘要**（端点与字段依据《探测报告-agedm》实测，完整代码见仓库 `src/plugins/sources/agedm/`）。

```ts
// src/plugins/sources/agedm/index.ts
import { manifest } from './manifest';
import * as m from './mapping';
import type { PluginContext, AnimeSourcePlugin } from '../../host/types';

const DEFAULT_API_BASE = 'https://api.agedm.io/v2/';   // 依据探测报告；旧 :2849 已废弃

export default function createPlugin(host: PluginContext): AnimeSourcePlugin {
  let base = DEFAULT_API_BASE;

  return {
    manifest,
    async init(config) {
      base = (typeof config.apiBaseUrl === 'string' && config.apiBaseUrl.trim())
        ? config.apiBaseUrl.trim().replace(/\/+$/, '') + '/'
        : DEFAULT_API_BASE;
    },
    // 周更表：home-list.week_list（键 "0"~"6"，0=周日；封面按 ID 规律构造）
    async getWeeklySchedule(page = 1) {
      if (page > 1) return { items: [], page, hasMore: false };
      const data = m.unwrap<m.AgedmHomeList>(await host.http.getJson<unknown>(base + 'home-list'), 'home-list');
      const items: AnimeSummary[] = [];
      for (const wd of Object.keys(data.week_list ?? {}).sort())
        for (const it of data.week_list![wd] ?? []) items.push(m.weekToSummary(it));
      return { items, page: 1, hasMore: false };
    },
    // 最新更新：update?page&size（裸结构，total 为字符串）
    async getLatestUpdates(page = 1) {
      const data = m.unwrap<m.AgedmUpdateList>(await host.http.getJson<unknown>(`${base}update?page=${page}&size=30`), 'update');
      return { items: (data.videos ?? []).map(m.updateToSummary), page, hasMore: Number(data.total) > page * 30 };
    },
    // 搜索：search?query&page（信封结构；参数名是 query 不是 keyword）
    async search(keyword, page = 1) {
      const data = m.unwrap<{ videos: m.AgedmSearchItem[] }>(
        await host.http.getJson<unknown>(`${base}search?query=${encodeURIComponent(keyword)}&page=${page}`), 'search');
      return { items: data.videos.map(m.searchToSummary), page, hasMore: data.videos.length >= 24 };
    },
    // 详情：detail/<AID>（信封结构；playlists 按线路分组）
    async getDetail(animeId) {
      const data = m.unwrap<m.AgedmDetailResponse>(await host.http.getJson<unknown>(`${base}detail/${encodeURIComponent(animeId)}`), 'detail');
      return m.toDetail(data);
    },
    // 播放：episodeId "l:e"（0-based）→ 源站 /#/play/<AID>/<l+1>/<e+1>（l/e 为 1-based，已实测）
    async resolvePlay(animeId, episodeId) {
      const d = m.toDetail(m.unwrap<m.AgedmDetailResponse>(
        await host.http.getJson<unknown>(`${base}detail/${encodeURIComponent(animeId)}`), 'detail'));
      const ep = d.episodes.find((e) => e.episodeId === episodeId);
      if (!ep?.playPageUrl) throw new PluginError('PARSE', `剧集不存在: ${animeId}:${episodeId}`);
      return { type: 'page', url: ep.playPageUrl };
    },
    // 扩展能力（§15）
    getCatalogMeta: () => buildCatalogFilters(),   // 地区/版本/首字母/年份
    async getCatalog(query, page = 1) { /* catalog?region&genre&letter&year&page&size */ },
    async getRank(year) { /* rank?year → 周榜/月榜/总榜 三组映射 */ },
  };
}
```

## 15. 扩展能力（v1.2）：分类与榜单

站点若有分类浏览或排行榜，可选实现以下扩展能力，并在 `manifest.capabilities` 声明 `catalog` / `rank`：

```ts
/** 分类筛选组定义（如 地区/版本/首字母/年份） */
interface CatalogFilterDef {
  key: string;                  // 查询参数键，如 "region"
  label: string;                // 展示名，如 "地区"
  options: Array<{ value: string; label: string }>;  // "all" 表示不限
}

/** 分类查询：key 为筛选组 key，值 "all" 表示不限 */
type CatalogQuery = Record<string, string>;

interface RankEntry {
  rankNo: number;               // 名次（1 起）
  animeId: string;
  title: string;
  score?: string;               // 热度/计数等展示值
}

interface RankGroup {
  name: string;                 // 榜单名，如 "周榜"
  entries: RankEntry[];
}

// 追加到 AnimeSourcePlugin 的可选方法：
getCatalogMeta?(): CatalogFilterDef[];
getCatalog?(query: CatalogQuery, page?: number): Promise<PagedResult<AnimeSummary>>;
getRank?(year?: string): Promise<RankGroup[]>;   // 不分页，一次返回全部榜单分组
```

约定：

- `getCatalog` 返回标准 `PagedResult`（分页语义同 §8 第 2 条），条目为 `AnimeSummary`（有封面则带）。
- `getRank` 无分页；榜单分组名由插件给出（源站无组名时按固定序命名，如 agedm 的 周榜/月榜/总榜）。
- 分类/榜单数据变化较慢，宿主方法级缓存缺省 TTL：`catalog` 600s、`rank` 1800s。
