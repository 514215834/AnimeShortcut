## 1. 迭代总览

项目按「小步快跑、每期可发布可验收」的节奏推进，共 5 期（迭代 0 ~ 迭代 4）。每期结束时应用都处于**可部署、可使用**状态；单期工作量按人日估算（1 人全职口径），供排期参考。

| 迭代 | 主题 | 核心交付 | 估算 | 依赖 |
| --- | --- | --- | --- | --- |
| 迭代 0 | 工程地基 | 脚手架、CI/CD 上线 GitHub Pages、agedm 连通性探测报告 | 1~2 人日 | 无 |
| 迭代 1 | MVP 看板 | 插件框架 + agedm 内置插件、看板首页、搜索、详情、跳转源站播放、代理链 | 3~5 人日 | 迭代 0 探测结论 |
| 迭代 2 | 追番个人化 | 订阅、观看历史、更新红点与提醒、排序过滤 | 2~4 人日 | 迭代 1 |
| 迭代 3 | 多源与站内播放 | 数据源管理页、第二个源、hls.js 站内播放、继续观看 | 3~5 人日 | 迭代 2 |
| 迭代 4 | 平台化增强 | PWA、深色模式、数据备份、图片代理优化、更多数据源 | 2~4 人日 | 迭代 3 |

> 每期内部任务顺序：先「数据与逻辑」（可测），后「页面与交互」（可见），保证进度可核对。

## 2. 迭代 0：工程地基

**目标**：空仓库 → 可自动发布的工程骨架，并消除 agedm 接口不确定性。

### 2.1 任务清单

| # | 任务 | 产出 | 验收标准 |
| --- | --- | --- | --- |
| 0-1 | 脚手架初始化 | Vue3 + Vite + TS + Pinia + vue-router(hash) + Tailwind 工程；`README.md`（含项目定位与本地开发说明） | `npm run dev` 可启动；`npm run build` 产出静态站点；TS 严格模式无报错 |
| 0-2 | 基础布局与路由骨架 | 顶部 Tab 导航 + 6 个空页面占位（见架构文档 §7 路由表） | 移动端与桌面端布局正常，路由切换无刷新错误 |
| 0-3 | GitHub Pages 流水线 | `.github/workflows/deploy.yml`；仓库 Pages 源设为 GitHub Actions | push main 后 10 分钟内线上可访问，非根路径刷新不 404 |
| 0-4 | **agedm 连通性探测** | `docs/探测报告-agedm.md` | 报告含：可用接口域名、各接口实测参数与返回样例、CORS 响应头实测、封面图防盗链结论、风险备注 |
| 0-5 | 架构落地评审 | （可选）根据探测结论修订技术架构文档 §4.1 与《数据源插件接口规范》示例 | 文档与实测一致 |

### 2.2 探测任务（0-4）执行步骤

1. 从 `m.agedm.io` 移动站抓包/读源码，定位其数据接口（页面内 XHR 与 JS 包中的 API 地址）。
2. 对每个候选接口用浏览器/curl 实测：带 `Origin` 请求头检查 `Access-Control-Allow-Origin` 响应头。
3. 记录返回结构字段 → 草拟 agedm 插件的能力声明（capabilities）与统一模型字段映射表（对应《数据源插件接口规范》）。
4. 验证封面图、播放页链接能否直连/直跳。
5. 若官方 API 不可用：评估备选路径（页面 HTML 解析、RSS、其他镜像域名），一并写入报告。

**退出条件**：明确「直连可用 / 需代理可用 / 均不可用需换源」三选一结论。若均不可用，迭代 1 启动前需与项目所有者确认更换数据源（见 §8 风险）。

## 3. 迭代 1：MVP 看板

**目标**：以 agedm 为唯一数据源，跑通「看板 → 搜索 → 详情 → 跳转播放」最小闭环。

### 3.1 功能点清单

| # | 功能点 | 说明 | 验收标准 |
| --- | --- | --- | --- |
| 1-1 | 网络请求管道 | 超时/重试/错误归一化 + 代理链（直连 → Worker → 公共代理回退，成功通道记忆） | 任一请求失败时 UI 能区分展示超时/网络/代理三类原因；代理切换对用户透明 |
| 1-2 | Worker 代理交付 | `worker/` 源码 + 部署指南（README 分节，含 Deploy 按钮） | 新用户按文档 10 分钟内部署完成并在设置页填入地址生效 |
| 1-3 | 两层缓存 | 内存 + localStorage TTL（策略见架构文档 §4.3） | 断网时冷启动仍能以缓存渲染看板，并标注缓存时间 |
| 1-4 | 插件框架 + agedm 内置插件 | 按《数据源插件接口规范》v1.0 实现插件宿主 PluginHost（清单校验、内置插件加载、能力协商、PluginContext 受限运行时）；agedm 作为首个内置插件：周更表 / 最新更新 / 搜索 / 详情 / 播放页地址，含夹具单测 | 夹具回放测试覆盖全部能力；真实环境看板数据与源站一致；宿主可加载、启停插件 |
| 1-5 | 看板首页 | 周更时间表（周一~周日 Tab + 未定档）+ 最新更新流（分页上拉加载） | 周几分组与源站一致；点番剧卡进入详情 |
| 1-6 | 搜索页 | 关键词搜索、结果列表、分页 | 结果与源站一致；空结果有引导态 |
| 1-7 | 详情页 | 封面/简介/标签/剧集列表/更新状态；「去源站播放」按钮 | 剧集列表与源站一致；点击剧集跳转源站对应播放页 |
| 1-8 | 设置页（基础） | 代理 Worker 地址、抓取频率、数据源启停开关 | 修改即生效并持久化，刷新后保留 |
| 1-9 | 全局体验件 | 骨架屏、错误态、空态、移动端适配 | 三态组件在所有页面统一复用 |

**迭代 1 验收演示路径**：打开站点 → 看板展示本周更新 → 搜索一部番 → 进入详情 → 点击剧集跳转源站播放页 → 断网刷新仍可见缓存内容。

## 4. 迭代 2：追番个人化

**目标**：让看板「为我所用」——订阅与更新提醒。

### 4.1 功能点清单

| # | 功能点 | 说明 | 验收标准 |
| --- | --- | --- | --- |
| 2-1 | 收藏订阅 | 详情页「追番」按钮；订阅页管理（取消、排序） | 订阅数据持久化（IndexedDB）；跨会话保留 |
| 2-2 | 观看历史 | 打开播放时记录（源+番+剧集+时间）；历史页与继续观看入口 | 历史按时间倒序；支持清空与单条删除 |
| 2-3 | 更新检测服务 | 页面可见时按频率抓取订阅番剧，与快照 diff（架构文档 §6） | 番剧更新后 ≤1 个抓取周期内出现红点；后台标签页不重复抓取 |
| 2-4 | 更新提醒 | 看板/订阅页角标数字 + Notification API 系统通知（可关） | 通知可一键关闭；未授权时静默降级为角标 |
| 2-5 | 已读指针 | 进入详情/播放后清除该番红点 | 红点状态跨设备一致性不要求（本地数据特性） |
| 2-6 | 列表增强 | 订阅/历史排序（按更新时间/加入时间）、筛选（连载中/完结）、虚拟滚动 | 200+ 条记录滑动不卡顿 |
| 2-7 | 三态完善 | 订阅页空态引导去看板；抓取连续失败提示检查代理 | — |

**迭代 2 验收演示路径**：追番 3 部 → 源站其中 1 部更新 → 打开看板出现角标与通知 → 点击进入详情红点清除。

## 5. 迭代 3：多源与站内播放

**目标**：从「单源工具」升级为「多源聚合看板」，并补齐站内播放体验。

### 5.1 功能点清单

| # | 功能点 | 说明 | 验收标准 |
| --- | --- | --- | --- |
| 3-1 | 数据源管理页 | 源列表（启停、状态探活、请求统计）；按源排序 | 停用某源后看板/搜索立即剔除该源数据 |
| 3-2 | 第二个数据源插件 | 按插件接口规范实现第二个站点的内置插件（候选由探测确定） | 与 agedm 并行聚合；各自夹具单测通过 |
| 3-3 | 多源合并 | 看板/搜索多源结果合并，按标题归并展示来源徽标；详情页显示来源与「换源查看」 | 同名番多源时卡片可见来源切换；单源失效不影响其余 |
| 3-4 | 站内播放（hls.js） | 详情页内嵌播放器播放 m3u8（动态 import）；倍速、记忆播放位置 | 插件能取到流地址的剧集可站内播放；取不到的自动回落跳转 |
| 3-5 | 继续观看 | 记录播放进度（localStorage），详情页/历史页「从第 N 集继续」 | 刷新后进度恢复（±5s 内） |
| 3-6 | 播放健壮性 | 防盗链/Referer 失败的检测与提示（回落跳转源站） | 播放失败 5 秒内给出可读原因与跳转按钮 |
| 3-7 | 外置远程插件（可选试点） | 设置页添加插件 URL → 权限确认 → Worker 沙箱加载（规范 §11）；默认关闭该入口 | 成功安装并运行一个示例远程插件；未经权限确认不加载 |

> 3-4/3-5 是本迭代**不确定性最高**的部分：若流地址有防盗链且 Worker 转发流量成本过高，允许裁剪为「跳转播放 + 继续观看（基于历史记录）」，记入迭代复盘。

## 6. 迭代 4：平台化增强

| # | 功能点 | 说明 | 验收标准 |
| --- | --- | --- | --- |
| 4-1 | PWA | Service Worker 离线壳、可安装到桌面/主屏 | 断网打开应用外壳正常；可安装 |

| 4-5 | 更多数据源插件 | 接入第 3+ 个源（走同一插件规范）；数据源插件管理增强 | 新增源无需改动业务层代码 |
| 4-6 | 站点国际化（可选） | 界面中英文切换 | — |

## 7. 每期通用验收标准（Definition of Done）

1. 代码通过 `npm run build` 与 `npm run test`（数据源插件夹具测试全绿）。
2. 功能演示路径（各期末尾给出）在真实 GitHub Pages 环境走通。
3. 新增功能有错误态/空态/加载态。
4. 不新增未评审的第三方大依赖。
5. 相关文档（架构/迭代计划/探测报告/插件接口规范）与本期实现一致，文档变更记录已更新。
6. 用户数据（订阅/历史/设置）在升级后不丢失（有 schemaVersion 迁移则验证迁移路径）。
7. 新增或变更的数据源插件符合《数据源插件接口规范》当前版本，并通过夹具测试门槛（规范 §13）。

## 8. 风险与应对

| # | 风险 | 影响 | 应对 | 兜底方案 |
| --- | --- | --- | --- | --- |
| 1 | agedm 接口均不可用且无备选 | 迭代 1 无法启动 | 迭代 0 先探测（见 §2.2） | 更换/增加数据源（樱花动漫等）；架构无需变动 |
| 2 | 公共代理不稳定 | 部分用户体验差 | 主推自部署 Worker | 设置页内置代理健康检查与提示 |
| 3 | 源站改版 | 看板数据异常 | 夹具测试 + 配置化接口 | 单源降级禁用，不影响多源整体 |
| 4 | 站内播放防盗链 | 迭代 3 裁剪 | 提前探测流地址可播放性 | 保留跳转播放路径 |
| 5 | 单人项目排期波动 | 迭代延迟 | 每期独立可发布 | 迭代 4 各项可独立拆出延后 |
| 6 | 外置远程插件的第三方代码风险 | 安全事件 | 页面数据被窃取/滥用 | 默认关闭、显式权限确认、Worker 沙箱与域名白名单（规范 §11） |

## 9. 迭代间协作约定

- 每期启动前：对照本文档列出本期任务到 issue/任务清单；文档修订走变更记录。
- 每期结束：按 §7 逐条验收，更新本文档状态列（进行中/已完成 + 完成日期）。
- 探测报告、探测发现的接口变更，优先更新 `docs/探测报告-agedm.md`、架构文档 §4.1 与《数据源插件接口规范》相关章节。
